## 33.1 动手前的三条约定

写 SSM 代码最容易犯的错不在数学，在形状和布局。先把约定钉死。

约定一，形状顺序。本章统一用

| 记号 | 形状 | 含义 |
|---|---|---|
| `B` | 标量 | batch size |
| `L` | 标量 | 序列长度 |
| `D` | 标量 | 模型维度（Mamba 里 `d_model`；内部展开后是 `d_inner = E·D`） |
| `N` | 标量 | SSM 状态维度（`d_state`） |
| `H` | 标量 | 通道数或 head 数（按上下文区分） |

S4D 的代码沿袭 S4 官方实现的习惯，把序列放在最后一维：输入 `(B, H, L)`，因为 `torch.fft` 在最后一维上工作最自然。Mamba 的代码沿袭 Transformer 习惯：`(B, L, D)`，因为 `nn.Linear` 作用在最后一维。两者在章节内部各自一致，跨节时我们会显式转置。

约定二，复数的处理方式。S4D 用复数 `A`，但只存一半。原因在第 14 章讲过：实 SSM 对角化后，特征值必然成共轭对出现，`(A_n, B_n, C_n)` 与 `(conj(A_n), conj(B_n), conj(C_n))` 贡献的核是共轭的，两者相加等于 `2·Re(·)`。所以状态维度 `N` 的模型只需要 `N/2` 个复数参数，参数量与 `N` 个实数完全相同，而输出自动是实数。这是 S4 系列最重要的工程技巧之一，代码里体现为最后那一句 `2.0 * K.real`。

约定三，符号沿用论文。第 17 章之后输入记作 $x_t$、状态记作 $h_t$，所以本章代码里 `x` 是输入、`h` 是状态、`A/B/C/dt` 是 SSM 参数。S4D 那一节因为要对照 S4D 论文的 Listing，仍用 $u$ 表示输入，这是全章唯一的例外。

## 33.2 S4D：把对角 SSM 写成四十行

### 33.2.1 参数化：为什么 A 要写成 `-exp(log_A_real) + i·A_imag`

连续时间 SSM 的核是 $K(t) = C e^{tA} B$。如果 $A$ 有任何一个特征值实部为正，$e^{tA}$ 就会随 $t$ 指数爆炸。训练时表现为 loss 突然变成 `nan`，推理时表现为生成的文本迅速退化成重复的乱码。S4D 论文 §3.3 明确把这条列为"稳定性约束"，并说这是控制论里的"左半平面条件（left-half plane condition）"。

解决办法是把实部塞进指数函数里：

$$A_n = -\exp(\texttt{log\_A\_real}_n) + i\cdot \texttt{A\_imag}_n$$

这样无论梯度把 `log_A_real` 推到多远，$-\exp(\cdot)$ 永远严格为负。论文还指出，`exp` 不是唯一选择，任何单侧有界的激活（ReLU、softplus）都可以，选 `exp` 只是因为它光滑且值域是 $(0,\infty)$。

`A_imag` 则完全自由，它控制基函数的振荡频率。S4D 论文 §4 的结论是虚部的分布比实部重要得多。随机初始化 $A$ 效果差，问题就出在虚部没有铺开：基函数挤在相近的频率上，等于用一组几乎线性相关的基去做投影。论文给了两个可用的初始化：

- S4D-Lin：$A_n = -\tfrac12 + i\pi n$，虚部取傅里叶级数的频率 $\pi n$。对应的基函数是"衰减的傅里叶基"，$e^{tA_n} = e^{-t/2}e^{i\pi n t}$。
- S4D-Real：$A_n = -(n+1)$，纯实数，虚部为零。这是 Mamba-1 论文 §3.6 推荐的默认值（"complex case 用 S4D-Lin，real case 用 S4D-Real"），因为语言这种离散模态并不需要复数的旋转结构。

下面这段代码是 S4D 论文 Listing 1 的 PyTorch 版本，我们补上了形状注释和参数化细节：

```python
import math
import torch
import torch.nn as nn
import torch.nn.functional as F


class S4DKernel(nn.Module):
    """S4D-Lin 的参数化与卷积核。

    只显式存 N/2 个复数状态，另外 N/2 个是它们的共轭；
    由于 (C B a^l) 与它的共轭相加等于 2*Re(.)，输出自然为实数。
    """

    def __init__(self, d_model, N=64, dt_min=1e-3, dt_max=1e-1):
        super().__init__()
        assert N % 2 == 0, "N 必须为偶数，才能两两配成共轭对"
        H, Nh = d_model, N // 2

        # (1) log_dt ~ Uniform[log dt_min, log dt_max]：在 log 尺度上均匀 = 几何均匀
        log_dt = torch.rand(H) * (math.log(dt_max) - math.log(dt_min)) + math.log(dt_min)

        # (2) S4D-Lin: A_n = -1/2 + i*pi*n。实部用 log 参数化，保证永远为负
        log_A_real = torch.full((H, Nh), math.log(0.5))
        A_imag = math.pi * torch.arange(Nh, dtype=torch.float32)

        # (3) C ~ N(0,1)（复数，实部虚部各自独立），B = 1
        C = torch.randn(H, Nh, dtype=torch.cfloat)

        self.H, self.N, self.Nh = H, N, Nh
        self.log_dt = nn.Parameter(log_dt)                       # (H,)
        self.log_A_real = nn.Parameter(log_A_real)               # (H,N/2)
        self.A_imag = nn.Parameter(A_imag.expand(H, Nh).clone()) # (H,N/2)
        self.C = nn.Parameter(C)                                 # (H,N/2) complex
        self.B = nn.Parameter(torch.ones(H, Nh))                 # (H,N/2)
```

还有几个细节容易被忽略。

`log_dt` 的采样是在对数上均匀做的。论文 Listing 1 写的是 `np.random.rand() * (log(dt_max)-log(dt_min)) + log(dt_min)`，即在**对数**上均匀。如果直接在 $[10^{-3}, 10^{-1}]$ 上均匀采样，99% 的样本会落在 $10^{-2}$ 附近，时间尺度的多样性就没了。几何均匀保证从毫秒到百毫秒每个数量级都有代表。这是所有 SSM 实现的标准做法，Mamba 的 `dt_proj.bias` 初始化用的是同一个分布。

`C` 的初始化标准差取 1，不是 $1/\sqrt{N}$，S4D 论文 §3.3 专门解释过：常规深度学习初始化会按维度缩放（比如 $1/\sqrt{N/2}$），但 S4 系列用的是方差保持（variance preserving）的初始化，标准差固定为 1。原因是 HiPPO 理论下 $\sum_n C_n K_n(t)$ 这一族基函数本身已经归一化好了，再乘 $1/\sqrt{N}$ 会把信号压得太小。论文说这个选择"是 HiPPO 理论的推论"，实现里照抄即可。

`B` 取 1 且可训练。S4D 论文对比了 DSS 的做法：DSS 直接把乘积 $W = B \odot C$ 当作参数，等价于冻结 $B=1$ 只训练 $C$。S4D 的消融显示"训练 $B$ 有一个微小但一致的提升"，所以这里把 `B` 也设成 `nn.Parameter`。

> 顺便记一处论文笔误：S4D 论文 Listing 1 里 `C = np.random.randn(N//2) + 1j * np.random.randn(N)`，第二个 `randn` 的参数写成了 `N`，与前半句的 `N//2` 不一致。从上下文（后面 `B*C` 要求同形状）看，这显然是排版错误，应为 `N//2`。我们上面的代码用的是 `(H, Nh)`。

### 33.2.2 离散化：双线性变换的公式与代码逐项对照

连续系统不能直接喂离散 token，必须先离散化。S4D 论文 §3.1 给了两个选项：

$$\text{(双线性)}\quad \bar A = \left(I - \tfrac{\Delta}{2}A\right)^{-1}\left(I + \tfrac{\Delta}{2}A\right),\qquad \bar B = \left(I - \tfrac{\Delta}{2}A\right)^{-1}\Delta B$$

$$\text{(ZOH)}\quad \bar A = e^{\Delta A},\qquad \bar B = A^{-1}\left(e^{\Delta A} - I\right)B$$

对角情形下这两个式子都退化成标量运算，逐元素算即可：

```python
    def discrete(self):
        """双线性（Tustin）离散化，返回 (A_bar, B_bar)，形状均为 (H,N/2) 复数。"""
        dt = torch.exp(self.log_dt).unsqueeze(-1)               # (H,1)
        A = -torch.exp(self.log_A_real) + 1j * self.A_imag      # (H,N/2)
        denom = 1.0 - dt * A / 2.0                              # (H,N/2)
        A_bar = (1.0 + dt * A / 2.0) / denom                    # (I - ΔA/2)^{-1}(I + ΔA/2)
        B_bar = dt * self.B / denom                             # (I - ΔA/2)^{-1} Δ B
        return A_bar, B_bar
```

公式和代码是一一对应的：`denom` 就是 $(I - \Delta A/2)$（对角矩阵，所以除法就是逐元素除法），`A_bar` 的分子是 $(I + \Delta A/2)$，`B_bar` 的分子是 $\Delta B$。`dt = exp(log_dt)` 则保证 $\Delta > 0$。

**双线性为什么在这里比 ZOH 好用？** 理由有三个：

1. 不用算矩阵指数。ZOH 需要对 $A$ 求 `expm`；当 $A$ 是 DPLR（对角加低秩）时这很贵，S4 论文为此专门设计了算法。双线性只用到 $(I - \Delta A/2)^{-1}$，对 DPLR 可以用 Woodbury 恒等式变成对角求逆加一次秩一修正。
2. 数值上更稳。双线性是所谓的"A-稳定"方法，它把左半平面精确映射到单位圆内，$|\bar A| < 1$ 恒成立。ZOH 也稳定，但当 $|\Delta A|$ 很大时 $\bar A \to 0$，梯度会消失；双线性则 $\bar A \to -1$，保留了符号信息。
3. S4D 论文 §4 图 2 报告了一个"curious phenomenon"：对 HiPPO-LegS 的对角近似，用双线性离散化得到的核，随着 $N\to\infty$ **精确地**收敛到 S4 的核，而 ZOH 不会。论文说这个现象"open for future work"，但它至少说明双线性不是随便选的。

S4D 论文 §3.1 还有个说法值得记：**"S4D 把离散化方法与核计算方法解耦了"**。这是 S4D 相对 DSS 的结构性优势。DSS 必须用 ZOH，因为 ZOH 里的 $\exp$ 项刚好能写成 softmax 的形式；而 S4D 的核计算（Vandermonde）与离散化无关，想换哪种就换哪种。我们上面的代码里 `discrete()` 和 `kernel()` 是两个独立方法，正是这个解耦的体现。

### 33.2.3 Vandermonde 卷积核：三种写法与显存账本

离散化之后，卷积核就是

$$\bar K_l = \sum_{n=0}^{N-1} C_n \bar A_n^{\,l} \bar B_n,\qquad l = 0,\dots,L-1$$

写成矩阵形式就是 $\bar K = (B \odot C)^\top V_L(\bar A)$，其中 $V_L(\bar A)$ 是 $N\times L$ 的 Vandermonde 矩阵，第 $(n,l)$ 项是 $\bar A_n^l$。这就是 S4D 论文式 (7)。

**最直白的写法**（论文 Listing 1 的一行）：

```python
    def kernel_naive(self, L):
        """朴素版：显式构造 (H, N/2, L) 的 Vandermonde 张量。显存 O(H*N*L)。"""
        A_bar, B_bar = self.discrete()
        powers = A_bar.unsqueeze(-1) ** torch.arange(L, device=A_bar.device)   # (H,N/2,L)
        K = (self.C.unsqueeze(-1) * B_bar.unsqueeze(-1) * powers).sum(dim=1)   # (H,L)
        return 2.0 * K.real                                                    # 共轭对相加
```

这行代码很优雅，但有一个致命问题：`powers` 这个张量的形状是 `(H, N/2, L)`。取 $H=256$、$N=64$、$L=4096$，它是 $256 \times 32 \times 4096 \approx 3.4\times 10^7$ 个复数，复数单精度占 8 字节，约 268 MB。而这只是**一层**的临时变量，反向传播时 PyTorch 还要为这个 `pow` 保存中间结果，显存直接翻倍。论文 §3.2 说得很清楚：朴素实现需要 $O(NL)$ 的**时间和空间**，而理论上 Vandermonde 乘向量只需要 $O(N+L)$ 空间。

省显存的写法利用了一个事实：$\bar A_n^l$ 关于 $l$ 是等比数列。对状态维做循环，每次只保留一条长度为 $L$ 的幂次向量：

```python
    def kernel(self, L):
        """省显存版：对状态维循环，只保留 (H,L) 的滚动幂次。显存 O(H*L)。"""
        A_bar, B_bar = self.discrete()                          # (H,N/2)
        K = torch.zeros(self.H, L, dtype=A_bar.dtype, device=A_bar.device)
        for n in range(self.Nh):
            # p[:, l] = A_bar_n^l，用 cumprod 一次算出整行
            p = torch.ones(self.H, L, dtype=A_bar.dtype, device=A_bar.device)
            if L > 1:
                p = torch.cat(
                    [p[:, :1], torch.cumprod(A_bar[:, n:n + 1].expand(self.H, L - 1), dim=-1)],
                    dim=-1,
                )
            K = K + (self.C[:, n] * B_bar[:, n]).unsqueeze(-1) * p
        return 2.0 * K.real
```

显存从 $O(HNL)$ 降到 $O(HL)$，代价是 Python 层多了一个长度为 $N/2$ 的循环。这个循环在 GPU 上会带来 $N/2$ 次 kernel launch 的开销（每次几微秒），$N=64$ 时约 32 次，还能接受；但如果 $N=256$，就变成 128 次，此时更常见的做法是把状态维也塞进一个块内（用 `torch.compile` 或自定义 kernel 把整个循环融进一个 kernel），或者干脆接受 $O(HNL)$ 的显存、只在小模型上用朴素版。

第三种写法是并行扫描。上面的 `cumprod` 本质上就是对 $(\bar A_n, \bar A_n, \dots)$ 这个序列做前缀积。前缀积是结合的（$(a_1 a_2)a_3 = a_1(a_2 a_3)$），因此可以用并行扫描在 $O(\log L)$ 深度内算完，第 19 章讲的 Blelloch 算法就是干这个的。在 PyTorch 里如果不想自己写，可以调用 `torch._higher_order_ops.associative_scan`（这是个私有 API，本章不依赖它）。

我们验证过三者的等价性：

两种写法在同一组参数下给出的核，最大误差 $1.5\times10^{-8}$；核与递推得到的冲激响应相比，最大误差 $3.0\times10^{-8}$。

第二行值得解释：把 $u = (1, 0, 0, \dots)$ 喂进递推 $h_t = \bar A h_{t-1} + \bar B u_t$，读出的 $y_t = \bar C h_t$ 应该正好等于 $\bar K_t$。数值上确实相等，说明"卷积核"与"冲激响应"是同一个东西，这正是第 3 章那个"一个系统、两种视角"的具体化。

### 33.2.4 FFT 因果卷积：为什么要补零到 2L

有了核，输出就是 $\bar K$ 与 $u$ 的因果卷积。直接调 `F.conv1d` 是 $O(L^2)$（因为核长也是 $L$），太慢。用 FFT 是 $O(L\log L)$：

```python
def fft_conv(u, K):
    """因果卷积 y_t = sum_{s<=t} K_{t-s} * u_s。

    u: (B,H,L)  K: (H,L) -> (B,H,L)
    补零到 2L 是为了避免 FFT 的循环卷积把尾部绕回开头。
    """
    L = u.shape[-1]
    u_f = torch.fft.rfft(u, n=2 * L)
    K_f = torch.fft.rfft(K, n=2 * L)
    return torch.fft.irfft(u_f * K_f, n=2 * L)[..., :L]
```

**为什么 `n=2*L`？** DFT 做的是**循环**卷积：长度 $L$ 的两个序列卷出来，下标 $t \ge L$ 的部分会绕回开头，污染前 $L$ 个结果。补零到 $2L$ 之后，线性卷积的结果长度是 $2L-1$，全部塞得下，不会绕回。然后只取前 $L$ 项，因为因果卷积的输出长度就是 $L$。

为什么只取前 $L$ 项就等于"因果"？因为核定义成 $\bar K_l = \bar C\bar A^l\bar B$，$l=0$ 对应"当前输入"，$l$ 增大对应"更久以前的输入"。卷积 $y_t = \sum_l \bar K_l u_{t-l}$ 里 $l$ 只取非负，意味着 $u_{t+1}$ 永远不会影响 $y_t$。补零卷积自动满足这一点，不需要额外的 mask。

代价是算了 $2L$ 个点、只用一半，浪费 2 倍算力。但 FFT 是 $O(L\log L)$，浪费常数因子 2 仍然远优于 $O(L^2)$。工程上这是标准做法；更省的做法是用 real-FFT 加一点技巧做到 $\tfrac{3}{2}L$ 的点数，收益不大，不值得。

我们验证了 FFT 卷积与 `F.conv1d`（把核翻转后当卷积核用）的等价性，最大误差 $4.8\times 10^{-8}$，是浮点噪声级别。

### 33.2.5 组装成一层 S4D

现在把上面几块拼起来。一层 S4D 需要三样东西：逐通道的 SSM 卷积、逐通道的 $D$ 跳连、以及一个跨通道的线性投影。

```python
class S4DLayer(nn.Module):
    """单层 S4D：逐通道独立的 SSM + D 跳连 + 输出投影（层间通道混合）。"""

    def __init__(self, d_model, N=64, dropout=0.0):
        super().__init__()
        self.kernel_fn = S4DKernel(d_model, N)
        self.D = nn.Parameter(torch.randn(d_model))      # 逐通道跳连，对应 ŷ = Cx + Du
        self.out_proj = nn.Linear(d_model, d_model)      # 唯一的跨通道混合
        self.dropout = nn.Dropout(dropout)

    def forward(self, u):
        # u: (B,H,L)  H 为通道数
        L = u.shape[-1]
        K = self.kernel_fn.kernel(L)                     # (H,L)
        y = fft_conv(u, K)                               # (B,H,L) 逐通道卷积
        y = y + u * self.D.unsqueeze(-1)                 # D 项
        y = self.dropout(self.out_proj(y.transpose(1, 2)))
        return y                                         # (B,L,H)
```

这里有一个常被忽略的设计点：SSM 部分是**逐通道独立**的。$H$ 个通道各有一套 $(A_h, B_h, C_h, \Delta_h)$，彼此之间没有任何信息交换。如果只有 SSM，这个层就退化成 $H$ 个互不相干的标量滤波器，表达能力非常有限。

所以 S4 系列的架构里必须有一步跨通道混合，就是那个 `out_proj`。S4 论文把它叫"位置线性混合"（position-wise linear mixing），本质是对每个时间步独立地做一次 $H\times H$ 的矩阵乘。它作用在时间维之后：先沿时间做卷积（每个通道独立），再沿通道做投影（每个时间步独立）。两个操作的作用维度是正交的，顺序其实可以交换，但先卷积后投影的显存更省（卷积不改变通道数）。

$D$ 项也值得说一句。它对应连续系统里的直通项 $\hat y(t) = Cx(t) + Du(t)$，在 S4 论文里被解释为"允许模型学习一个纯跳连，让 SSM 部分专注于长程记忆"。初值取 `randn` 而不是 0，是为了打破对称性：若 $D=0$，训练初期梯度只能通过 $C$ 传回去，收敛会慢一些。

再往上就是一个标准的 pre-norm 残差块：

```python
class S4DBlock(nn.Module):
    """Pre-norm 残差块：SSM 混合 + 逐位置 MLP。"""

    def __init__(self, d_model, N=64, expand=2, dropout=0.0):
        super().__init__()
        self.norm1 = nn.LayerNorm(d_model)
        self.mixer = S4DLayer(d_model, N, dropout)
        self.norm2 = nn.LayerNorm(d_model)
        self.fc1 = nn.Linear(d_model, expand * d_model)
        self.fc2 = nn.Linear(expand * d_model, d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x):                                # (B,L,H)
        x = x + self.mixer(self.norm1(x).transpose(1, 2))
        h = self.fc2(self.dropout(F.gelu(self.fc1(self.norm2(x)))))
        return x + h
```

为什么 SSM 层前面要 LayerNorm？因为 $C$ 的初始化是标准差 1（不随维度缩小），这意味着 SSM 层的输出量级会随 $N$ 增长。如果不归一化，深堆几层就会爆。这也是 S4 论文里"SSM 层需要特殊照顾"的一个具体体现。

### 33.2.6 端到端训练骨架

最后给一个能跑的 sequential MNIST 分类器。sMNIST 是 SSM 论文的标准测试台：把 $28\times 28$ 的图像按行摊平成 784 步序列，每步一个像素，做 10 分类。S4 论文 Table 12 报告 sMNIST 99.63（pMNIST 98.70、sCIFAR 91.13）；S4D 论文 §5 的结论是它的最好变体在这些任务上与 S4 相当。我们不复现这些数字，只给骨架。

```python
class S4DClassifier(nn.Module):
    """把 sMNIST 的像素序列 (B,L,1) 映射到 (B,n_class)。"""

    def __init__(self, d_input=1, d_model=64, n_layer=4, N=64, n_class=10):
        super().__init__()
        self.input_proj = nn.Linear(d_input, d_model)
        self.blocks = nn.ModuleList([S4DBlock(d_model, N) for _ in range(n_layer)])
        self.norm_f = nn.LayerNorm(d_model)
        self.head = nn.Linear(d_model, n_class)

    def forward(self, u):                                # (B,L,d_input)
        x = self.input_proj(u)
        for blk in self.blocks:
            x = blk(x)
        x = self.norm_f(x)
        return self.head(x.mean(dim=1))                  # 时间维平均池化
```

训练循环：

```python
import torch
import torch.nn.functional as F
from torch.utils.data import DataLoader, TensorDataset


def make_dummy_smnist(n=512, length=784, n_class=10):
    """占位数据：真实场景换成 torchvision 的 MNIST，把 28x28 摊平成 784 步序列。"""
    x = torch.randn(n, length, 1)
    y = torch.randint(0, n_class, (n,))
    return TensorDataset(x, y)


def train(model, loader, epochs=1, lr=3e-4, device="cpu"):
    model.to(device)
    opt = torch.optim.AdamW(model.parameters(), lr=lr, weight_decay=0.01)
    for epoch in range(epochs):
        model.train()
        for step, (x, y) in enumerate(loader):
            x, y = x.to(device), y.to(device)
            logits = model(x)
            loss = F.cross_entropy(logits, y)
            opt.zero_grad(set_to_none=True)
            loss.backward()
            # 梯度裁剪对 SSM 尤其重要：Δ 的梯度容易尖峰
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            opt.step()
            if step % 20 == 0:
                acc = (logits.argmax(-1) == y).float().mean().item()
                print(f"epoch {epoch} step {step} loss {loss.item():.4f} acc {acc:.3f}")
```

三个实践提醒：

1. 梯度裁剪不能省。$\bar A = (1+\Delta A/2)/(1-\Delta A/2)$ 对 $\Delta$ 的导数在 $\Delta A \to 2$ 时会爆炸（分母趋零）。虽然参数化保证 $\Delta A$ 的实部为负、分母不会真的到零，但虚部大时仍可能出现接近奇点的情况。裁剪到 1.0 是安全网。
2. 学习率要小。S4 论文用的是 1e-3 到 1e-4 量级，且带 warmup。原因同上：$\Delta$ 的梯度尺度与 $A$ 耦合，初期不稳。
3. `N` 不要设太小。sMNIST 上 S4 用 $N=64$，LRA 上用到 256 甚至 512。$N$ 是"记忆容量"，太小就记不住 784 步前的像素。

## 33.3 S6：把"时不变"改成"时变"

### 33.3.1 从 Algorithm 1 到 Algorithm 2 的实质变化

Mamba 论文的 Algorithm 1 和 Algorithm 2 只差四行，差别却全在这四行里。并排放一下：

| 步骤 | Algorithm 1（S4） | Algorithm 2（S6） |
|---|---|---|
| 1 | $A:(D,N)$ 参数 | $A:(D,N)$ 参数 |
| 2 | $B:(D,N)$ 参数 | $B:(B,L,N) \leftarrow s_B(x)$ |
| 3 | $C:(D,N)$ 参数 | $C:(B,L,N) \leftarrow s_C(x)$ |
| 4 | $\Delta:(D) \leftarrow \tau_\Delta(\text{Parameter})$ | $\Delta:(B,L,D) \leftarrow \tau_\Delta(\text{Parameter}+s_\Delta(x))$ |
| 5 | $\bar A,\bar B:(D,N) \leftarrow \text{discretize}$ | $\bar A,\bar B:(B,L,D,N) \leftarrow \text{discretize}$ |
| 6 | $y \leftarrow \text{SSM}(x)$，**递推或卷积** | $y \leftarrow \text{SSM}(x)$，**只能递推（scan）** |

看第 2、3、4 行：$B, C, \Delta$ 都多出了一个 $L$ 维。第 5 行：离散化后的参数也带上了 $L$ 维。第 6 行括号里那句注释是全章的题眼：**"Time-invariant: recurrence or convolution" 变成了 "Time-varying: recurrence (scan) only"**。

为什么卷积不行了？卷积定理要求系统是时不变的：$y = \bar K * u$ 里那个 $\bar K$ 必须与位置无关。一旦 $\bar A_t$ 依赖 $t$，核就变成 $\bar K_{t,s} = \bar C_t \bar A_t \cdots \bar A_{s+1}\bar B_s$，它是 $(t,s)$ 的二元函数，不再是 $\bar K_{t-s}$ 的一元函数。你没法用一次 FFT 算完一个 $L\times L$ 的矩阵乘向量，除非退化成 $O(L^2)$。

这就是 Mamba 付出的代价：放弃卷积带来的 $O(L\log L)$ 训练路径，换回 $O(L)$ 的扫描。第 19 章讲过这笔账怎么算：朴素递推是 $O(BLDN)$ FLOPs，卷积是 $O(BLD\log L)$，当 $L$ 不太大而 $N$ 不太小时，递推的 FLOPs 其实更少，Mamba 论文 §3.3.2 明确说了这一点。真正的问题不在 FLOPs，在**顺序依赖**和**显存**。

### 33.3.2 离散化：指数-欧拉，以及它与 ZOH 的差别

Mamba 论文式 (4) 写的是

$$\bar A = \exp(\Delta A),\qquad \bar B = (\Delta A)^{-1}\left(\exp(\Delta A) - I\right)\cdot \Delta B$$

这是标准的 ZOH。但实现里不是这么算的。Mamba-3 论文 §3.1 把这个历史公案讲清楚了，结论值得完整引一遍：

- 论文正文写 ZOH，但代码里用的是 $\bar B = \Delta B$（Mamba-3 论文脚注 3 直接指出 "While the Mamba-1 paper reports ZOH discretization, the implementation follows github.com/state-spaces/mamba/issues/129"）。
- Mamba-3 论文 Table 1 把这种做法正式命名为 exponential-Euler（指数-欧拉）：先用指数精确解状态转移，再用欧拉法近似状态-输入积分，得到 $\alpha_t = e^{\Delta_t A_t}$、$\gamma_t = \Delta_t$，即

$$h_t = e^{\Delta_t A_t}h_{t-1} + \Delta_t B_t x_t$$

- 两者的差别在**对输入的积分精度**：ZOH 假设输入在区间内为常数并精确积分（得到 $A^{-1}(e^{\Delta A}-I)$），欧拉法只取右端点乘以区间长度（得到 $\Delta$）。当 $\Delta A$ 很小时两者几乎相同（泰勒展开一阶相同），当 $|\Delta A|$ 不小的时候差别就出来了。Mamba-3 论文 §3.1.1 还指出，欧拉法的局部截断误差是 $O(\Delta^2)$，而 Mamba-3 的指数-梯形法是 $O(\Delta^3)$。

在代码里，这个差别就是一行：

```python
        dA = torch.exp(dt[:, t, :, None] * A)                  # Ā = exp(ΔA)
        dB = dt[:, t, :, None] * Bm[:, t, None, :]             # B̄ = Δ·B  ← 指数-欧拉
```

如果是 ZOH，第二行要写成 `(torch.exp(dt*A) - 1) / A * Bm`。后者在 $A \to 0$ 时是 $0/0$，需要额外处理；前者永远安全。这是工程上选指数-欧拉的另一个理由，虽然论文没明说。

### 33.3.3 参数与初始化：那些不起眼但要命的细节

```python
class S6Recurrent(nn.Module):
    """最易读的 S6：时间维 for 循环 + 状态缓存。慢，但每一步在干什么一目了然。"""

    def __init__(self, d_inner, d_state=16, dt_rank=None, conv_kernel=4):
        super().__init__()
        self.d_inner, self.d_state = d_inner, d_state
        self.dt_rank = dt_rank if dt_rank is not None else max(1, math.ceil(d_inner / 16))
        self.conv_kernel = conv_kernel

        # Δ、B、C 都由 x 投影得到（选择性）；一次投影切三段省一次 kernel launch
        self.x_proj = nn.Linear(d_inner, self.dt_rank + 2 * d_state, bias=False)
        self.dt_proj = nn.Linear(self.dt_rank, d_inner, bias=True)

        # A = -exp(A_log)：A_log 初始化为 log(1..N)，于是 A = -(1..N)，负实部
        A = torch.arange(1, d_state + 1, dtype=torch.float32).repeat(d_inner, 1)
        self.A_log = nn.Parameter(torch.log(A))          # (D,N)
        self.D = nn.Parameter(torch.ones(d_inner))       # (D,)

        # depthwise 因果卷积：groups=d_inner 意味着每个通道一条独立卷积核
        self.conv1d = nn.Conv1d(d_inner, d_inner, conv_kernel,
                                groups=d_inner, padding=conv_kernel - 1, bias=True)

        # Δ 的 bias 初始化成 softplus^{-1}(loguniform[1e-3,1e-1])
        dt = torch.exp(torch.rand(d_inner) * (math.log(1e-1) - math.log(1e-3)) + math.log(1e-3))
        with torch.no_grad():
            self.dt_proj.bias.copy_(dt + torch.log(-torch.expm1(-dt)))
```

逐项解释。

`dt_rank` 取 $\lceil d_{\text{inner}}/16 \rceil$。Mamba 论文 §3.6 说 $s_\Delta(x) = \text{Broadcast}_D(\text{Linear}_1(x))$，即先降到 1 维再广播。但 1 维太死板，论文说"可以推广到更大的维度 $R$，取 $D$ 的一小部分"。官方实现取 $R = \lceil D/16 \rceil$。这个设计的用意是让所有通道共享一个低秩的 $\Delta$ 调制信号，因为 $\Delta$ 的语义是"这个 token 重要吗"，它更接近一个全局判断而非逐通道判断。论文 §3.5 说得很直白："if a given input $x_t$ should be completely ignored, all $D$ channels should ignore it, and so we project the input down to 1 dimension before repeating/broadcasting"。

`A_log` 初始化成 `log(1..N)`，于是 $A = -(1, 2, \dots, N)$，这正是 S4D-Real 的初始化 $-(n+1)$（$n$ 从 0 起）。Mamba 论文 §3.6 说实值情形默认用 S4D-Real。Table 8 的消融很有意思：S4D-Lin（复数）在语言建模上困惑度 9.16，S4D-Real 8.85，$-(n+1)$ 8.71，随机初始化也是 8.71。所以语言这种离散模态确实不需要复数的旋转结构。

`dt_proj.bias` 的初始化看着奇怪，原因是我们要让 softplus 之后的 $\Delta$ 服从 $\text{loguniform}[10^{-3}, 10^{-1}]$。bias 是加在 softplus **之前**的，所以需要反函数：若 $y = \text{softplus}(b)$，则 $b = y + \log(1 - e^{-y}) = y + \log(-\text{expm1}(-y))$。这就是那行 `dt + torch.log(-torch.expm1(-dt))`。$\text{expm1}(x) = e^x - 1$ 在 $x\to 0$ 时精度远好于 $e^x - 1$，所以必须用 `expm1` 而不是直接减。

`conv1d` 的 `groups=d_inner` 是 depthwise 卷积：每个通道一条独立的长度为 4 的卷积核，通道之间不混合。它的作用是给 SSM 提供一点"局部上下文"，因为 SSM 本身是因果的逐点递推，对相邻几个 token 的局部模式（比如字符 bigram）不敏感。Mamba-3 论文 §3.4 说，加了 B/C 的偏置和指数-梯形离散化之后，这个短卷积就"变得可选"了（Table 5a：完整模型 15.72，加回卷积 15.85，反而略差）。

### 33.3.4 顺序递推版：慢，但能看清每一步

```python
    def forward(self, x):                                # (B,L,D)
        B_, L, D = x.shape
        xc = F.silu(self.conv1d(x.transpose(1, 2))[..., :L]).transpose(1, 2)
        x_dbl = self.x_proj(xc)
        dt, Bm, Cm = torch.split(x_dbl, [self.dt_rank, self.d_state, self.d_state], dim=-1)
        dt = F.softplus(self.dt_proj(dt))                # (B,L,D) 恒正
        A = -torch.exp(self.A_log)                       # (D,N) 恒负
        h = x.new_zeros(B_, D, self.d_state)             # (B,D,N) 状态缓存
        ys = []
        for t in range(L):
            dA = torch.exp(dt[:, t, :, None] * A)                  # (B,D,N)
            dB = dt[:, t, :, None] * Bm[:, t, None, :]             # (B,D,N)
            h = dA * h + dB * xc[:, t, :, None]                    # h_t = Ā h_{t-1} + B̄ x_t
            ys.append(torch.einsum('bdn,bn->bd', h, Cm[:, t]))     # y_t = C_t · h_t
        return torch.stack(ys, dim=1) + xc * self.D
```

`h` 的形状是 `(B, D, N)`，不是 `(B, L, D, N)`。状态只在时间维上滚动，不保留历史。$L=10000$ 时，`h` 仍然只有 $B\times D\times N$ 个元素。这正是 SSM 相对 Transformer 的核心优势：推理时内存与序列长度无关。

这个版本在 CPU 上跑 $L=784$ 大概要几百毫秒；GPU 上因为每步只有一次极小的逐元素运算，利用率不到 1%，比并行版慢几十倍。它唯一的用途是当参考实现：任何并行版都应该和它的输出对得上。

### 33.3.5 并行版之一：二次型（segsum）

要并行，就得把递推展开成矩阵形式。展开 $h_t = \sum_{s\le t}\left(\prod_{s<i\le t}\bar A_i\right)\bar B_s x_s$，再乘 $C_t$：

$$y_t = \sum_{s\le t} C_t^\top\left(\prod_{s<i\le t}\bar A_i\right)\bar B_s\, x_s$$

对角情形下 $\bar A_i$ 是标量（每个通道、每个状态一个），乘积变成 $\exp\left(\sum_{s<i\le t}\Delta_i A\right)$。而"区间和"可以用两次前缀和相减得到，这就是 `segsum` 的全部内容：

```python
def segsum(x):
    """x: (..., T) -> (..., T, T)，元素 [t,s] = sum_{s<i<=t} x_i（t>=s），上三角为 -inf。

    这是 Mamba-2 论文 Listing 1 的第一行，也是理解 1-SS 矩阵的最小工具。
    """
    T = x.size(-1)
    x_cumsum = torch.cumsum(x, dim=-1)
    x_segsum = x_cumsum[..., :, None] - x_cumsum[..., None, :]
    mask = torch.tril(torch.ones(T, T, device=x.device, dtype=bool), diagonal=0)
    return x_segsum.masked_fill(~mask, -torch.inf)
```

逐行看：

1. `x_cumsum = cumsum(x)`：得到 $S_t = \sum_{i\le t} x_i$。
2. `x_cumsum[..., :, None] - x_cumsum[..., None, :]`：广播成 $S_t - S_s$，即 $\sum_{s<i\le t}x_i$。$t=s$ 时结果是 0，$t<s$ 时是负的区间和。
3. `masked_fill(~mask, -inf)`：把上三角（$t<s$）填成 $-\infty$。取 `exp` 之后变成 0，正好实现因果掩码。

有个地方容易搞错：`segsum` 给的是 $\sum_{s<i\le t}$，不含 $s$ 本身。这个约定对应"从 $s$ 到 $t$ 的转移要乘 $\bar A_{s+1}\cdots\bar A_t$"，第 $s$ 步的输入是直接加进状态的、不经过衰减。实现里必须让 `log_decay` 的索引对齐这个约定，否则会差一个 $\Delta_s A$ 的因子，这是最常见的 off-by-one 错误。

有了 `segsum`，二次型实现就是把上面那个双重求和写成一个 einsum：

```python
def s6_quadratic(x, dt, Bm, Cm, A):
    """x:(B,L,D) dt:(B,L,D) Bm:(B,L,N) Cm:(B,L,N) A:(D,N) -> (B,L,D)"""
    B_, L, D = x.shape
    N = A.shape[1]
    xT, dtT = x.transpose(1, 2), dt.transpose(1, 2)             # (B,D,L)
    y = x.new_zeros(B_, D, L)
    for n in range(N):
        log_decay = dtT * A[:, n].view(1, D, 1)                 # (B,D,L)
        M = torch.exp(segsum(log_decay))                        # (B,D,L,L)
        Cn = Cm[:, :, n].unsqueeze(1)                           # (B,1,L)
        dBn = dtT * Bm[:, :, n].unsqueeze(1)                    # (B,D,L)
        G = Cn.unsqueeze(-1) * dBn.unsqueeze(-2) * M            # (B,D,L,L)
        y = y + torch.einsum('bdts,bds->bdt', G, xT)
    return y.transpose(1, 2)
```

`G` 就是"注意力分数矩阵"：$G_{t,s} = C_{t,n}\cdot \Delta_s B_{s,n}\cdot e^{\sum_{s<i\le t}\Delta_i A_n}$。第 24 章讲的状态空间对偶，说的就是这个矩阵：它和 $\text{softmax}(QK^\top)$ 的位置完全对应，只是把 softmax 换成了固定的衰减。

这个版本的致命缺陷是显存。`M` 和 `G` 都是 $(B,D,L,L)$。取 $B=8$、$D=2048$、$L=4096$，单个张量就是 $2.7\times 10^{11}$ 个元素，不可能。即使 $L=1024$，也是 $1.7\times 10^{10}$，16 GB 都放不下。

所以真实实现必须做两件事：(a) 不在状态维上循环（把 $N$ 折进 einsum 的收缩维，避免 $N$ 倍的中间张量），(b) 分块，让 $L\times L$ 变成 $C\times C$ 加上一个长度 $L/C$ 的递推。这就是 SSD，也是下一节的内容。

我们验证过二次型与递推的等价性：用本节代码在 $D=8$、$N=4$、$L=12$ 上跑，最大绝对误差是 $9.3\times 10^{-10}$；把 $\Delta$ 放大后误差会升到 $10^{-6}$ 量级。两者都只是 float32 的累积误差，不是公式错。

### 33.3.6 并行版之二：`cumsum` 除法技巧，以及它为什么会崩

还有一个更"取巧"的并行写法。把递推除以累积衰减：

$$h_t = \left(\prod_{i\le t}\bar A_i\right)\sum_{s\le t}\frac{\bar B_s x_s}{\prod_{i\le s}\bar A_i}$$

右边是一个前缀和，`torch.cumsum` 一次搞定，$O(L)$ 显存、$O(L)$ 深度。看起来很完美，但它会崩。实测：取 $A=-2$、$\Delta=0.5$，$\bar A = e^{-1}\approx 0.368$，跑 600 步后 $\prod \bar A_i \approx e^{-600}$，在 float32 下下溢成 0。除零得到 `inf`，再乘回 0 得到 `nan`。

复现时如果直接在实数域连乘 $\bar A$，会看到 `cumA` 的最小值变成 0，输出与参考值相差 4.67（同量级意味着完全错误），但不会出现 `nan`。下溢最危险的地方就在这里：它不报错。

第三行值得解释。用了 `cumA.clamp_min(1e-30)` 避免除零，于是 `1/cumA` 变成 $10^{30}$ 而不是 `inf`，结果没有 `nan`，但错得更隐蔽：`cumA * S` 里那个 0 把巨大的 `S` 又乘回 0，输出全是 0。如果不用 clamp，你会得到 `inf`/`nan`，至少还能立刻发现。最危险的 bug 是那个不报错、loss 还在缓慢下降的 bug。

这个例子说明一件事：并行算法的数值稳定性不属于数学问题，属于浮点问题。数学上等价的两种写法，一种在 $L=600$ 时就废了，另一种（分块）不会，因为分块把累积乘积的长度限制在 $C=64$ 以内，$\bar A^{64}$ 对 $\bar A=0.368$ 是 $10^{-28}$，还在 float32 的范围内（最小正规数约 $10^{-38}$）。

这也解释了为什么 SSD 一定要分块，而不能用"全局 cumsum"取巧。

### 33.3.7 分块版：SSD 的雏形

分块版的思路是：把序列切成 $L/C$ 个块，每块内部用二次型（$C\times C$ 很小），块之间用递推（只有 $L/C$ 步）。

```python
def s6_chunked(x, dt, Bm, Cm, A, chunk=16):
    B_, L, D = x.shape
    N = A.shape[1]
    pad = (chunk - L % chunk) % chunk
    if pad:
        x = F.pad(x, (0, 0, 0, pad)); dt = F.pad(dt, (0, 0, 0, pad))
        Bm = F.pad(Bm, (0, 0, 0, pad)); Cm = F.pad(Cm, (0, 0, 0, pad))
    nc = (L + pad) // chunk
    x = x.view(B_, nc, chunk, D); dt = dt.view(B_, nc, chunk, D)
    Bm = Bm.view(B_, nc, chunk, N); Cm = Cm.view(B_, nc, chunk, N)

    dtA = dt.unsqueeze(-1) * A.view(1, 1, 1, D, N)              # (B,nc,C,D,N)
    LA = torch.cumsum(dtA, dim=2)                               # 块内累积 log 衰减
    Lmask = torch.exp(segsum(dtA.permute(0, 1, 3, 4, 2)))       # (B,nc,D,N,C,C)
    v = dt.unsqueeze(-1) * x.unsqueeze(-1) * Bm.unsqueeze(3)    # (B,nc,C,D,N)
    # (1) 块内（对角块）：注意力式
    Yd = torch.einsum('bctn,bcsdn,bcdnts->bctd', Cm, v, Lmask)
    # (2) 块末状态
    dec = torch.exp(LA[:, :, -1:, :, :] - LA)                   # (B,nc,C,D,N)
    st = torch.einsum('bcsdn,bcsdn->bcnd', v, dec)              # (B,nc,N,D)
    # (3) 块间递推 + (4) 状态到输出
    h = x.new_zeros(B_, N, D)
    outs = []
    for c in range(nc):
        Yo = torch.einsum('btn,btdn,bnd->btd', Cm[:, c], torch.exp(LA[:, c]), h)
        outs.append(Yd[:, c] + Yo)
        h = h * torch.exp(LA[:, c, -1]).permute(0, 2, 1) + st[:, c]
    return torch.cat(outs, dim=1)[:, :L], h
```

四个步骤与 Mamba-2 论文 §6 的四个小节严格对应（下一节会逐条对照）。用本节代码在 $D=8$、$N=4$、$L=20$、`chunk=8` 上测，与递推版的输出误差是 $4.7\times 10^{-10}$，末状态误差同量级。

这个版本仍然有 $N$ 倍的中间张量（`Lmask` 是 `(B,nc,D,N,C,C)`），所以还不是真正的 SSD。真正的 SSD 要把 `C` 和 `B` 先收缩掉，让 $N$ 只出现在两次矩阵乘的收缩维里——这就需要用 Mamba-2 论文的 einsum 写法。

### 33.3.8 门控与 block

Mamba block 就是把 SwiGLU 的 MLP 换成 SSM。SwiGLU 是 `out = W2(SiLU(W1 x) * W3 x)`；Mamba 把 `SiLU(W1 x)` 换成 `SSM(conv(SiLU(W1 x)))`：

```python
class RMSNorm(nn.Module):
    def __init__(self, d_model, eps=1e-5):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(d_model))

    def forward(self, x):
        return self.weight * x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)


class MambaBlock(nn.Module):
    """一个 Mamba block：in_proj -> (conv+SiLU -> S6) 与 (SiLU 门) -> 相乘 -> out_proj。"""

    def __init__(self, d_model, d_state=16, expand=2, conv_kernel=4, chunk=64):
        super().__init__()
        self.d_model = d_model
        self.d_inner = int(expand * d_model)
        self.d_state = d_state
        self.dt_rank = max(1, math.ceil(self.d_inner / 16))
        self.conv_kernel = conv_kernel
        self.chunk = chunk

        self.norm = RMSNorm(d_model)
        self.in_proj = nn.Linear(d_model, 2 * self.d_inner, bias=False)
        self.conv1d = nn.Conv1d(self.d_inner, self.d_inner, conv_kernel,
                                groups=self.d_inner, padding=conv_kernel - 1, bias=True)
        self.x_proj = nn.Linear(self.d_inner, self.dt_rank + 2 * d_state, bias=False)
        self.dt_proj = nn.Linear(self.dt_rank, self.d_inner, bias=True)
        A = torch.arange(1, d_state + 1, dtype=torch.float32).repeat(self.d_inner, 1)
        self.A_log = nn.Parameter(torch.log(A))
        self.D = nn.Parameter(torch.ones(self.d_inner))
        self.out_proj = nn.Linear(self.d_inner, d_model, bias=False)

        dt = torch.exp(torch.rand(self.d_inner) * (math.log(1e-1) - math.log(1e-3)) + math.log(1e-3))
        with torch.no_grad():
            self.dt_proj.bias.copy_(dt + torch.log(-torch.expm1(-dt)))

    def forward(self, u):                                # (B,L,d_model)
        B_, L, _ = u.shape
        xz = self.in_proj(self.norm(u))
        x, z = xz.chunk(2, dim=-1)                       # (B,L,d_inner) x2
        xc = F.silu(self.conv1d(x.transpose(1, 2))[..., :L]).transpose(1, 2)
        x_dbl = self.x_proj(xc)
        dt, Bm, Cm = torch.split(x_dbl, [self.dt_rank, self.d_state, self.d_state], dim=-1)
        dt = F.softplus(self.dt_proj(dt))
        A = -torch.exp(self.A_log)
        y, _ = s6_chunked(xc, dt, Bm, Cm, A, chunk=self.chunk)
        y = (y + xc * self.D) * F.silu(z)
        return self.out_proj(y)
```

残差与归一化的摆放值得单独说。Mamba 用 pre-norm：`x = x + block(norm(x))`。`norm` 在 block **内部**（`self.norm`），残差在 block 外部。这一点和 Transformer 一样，但 Mamba 的 block 内部只有一次归一化，输出投影前没有第二次。Mamba-2 补上了这一层（NormFormer 式），第 34 章会讲为什么。

`expand=2` 的来历也算得出来。Mamba 论文 §3.4 说"我们总是固定 $E=2$，并用两个 block 堆叠来匹配 Transformer 的 MHA+MLP 的 $12D^2$ 参数"。一个 Mamba block 的参数约 $3ED^2 = 3\cdot 2D^2 = 6D^2$（输入投影 $2ED^2$ + 输出投影 $ED^2$），两个就是 $12D^2$，正好等于 Transformer 一层注意力（$4D^2$）+ 一层 MLP（$8D^2$）。这个对齐是为了做公平的缩放律对比。

### 33.3.9 训练用并行、推理用递推

训练与推理用不同实现，是理解整个 Mamba 系列系统设计的入口。

**训练时**手里有整段序列，要算所有位置的输出，还要反传。递推版的问题不在 FLOPs：

1. 串行。$L$ 步必须依次算，GPU 的几千个核大部分时间在等。$L=4096$ 时，理论并行度是 1，实际 GPU 利用率不到 1%。
2. 中间状态占显存。反传需要每个 $h_t$，形状 $(B,L,D,N)$。$B=8, L=4096, D=2048, N=16$ 时是 $1.07\times 10^{9}$ 个元素，bf16 下 2 GB，而这是**一层**的量。

所以训练必须用并行形式（二次型或分块），让时间维变成矩阵乘的一维，交给 Tensor Core。

**推理时**情况反过来。自回归生成每次只来一个 token，根本凑不出一段序列去并行。这时递推版是最优的：

```python
def decode_step(x_t, h, dt_proj, x_proj, A, B_t, C_t):
    """单步解码：x_t: (B,D)；h: (B,N,D) 上一时刻的状态；B_t/C_t: (B,N)。
    返回 y_t (B,D) 与新状态 h (B,N,D)。"""
    dt = F.softplus(dt_proj(x_proj(x_t)))               # (B,D)
    dA = torch.exp(dt.unsqueeze(-1) * A)                # (B,D,N)
    dB = dt.unsqueeze(-1) * B_t.unsqueeze(1)            # (B,D,N)
    # 换到 (B,N,D) 布局，与 h 对齐
    h = dA.permute(0, 2, 1) * h + dB.permute(0, 2, 1) * x_t.unsqueeze(1)
    y = torch.einsum('bn,bnd->bd', C_t, h)              # (B,D)
    return y, h
```

SSM 与 Transformer 最本质的差别体现在缓存上。两种缓存并排如下：

| | Transformer（MHA） | SSM（Mamba） |
|---|---|---|
| 缓存内容 | 每层的 $K, V$，长度随 $t$ 增长 | 每层一个固定形状的 $h$ |
| 缓存大小 | $2 \times n_{\text{layer}} \times n_{\text{head}} \times d_{\text{head}} \times t$ | $n_{\text{layer}} \times D \times N$ |
| 随 $t$ 增长 | 线性 | **常数** |
| 每步计算量 | $O(t\cdot d)$ | $O(D\cdot N)$ |

算个具体数字。$D=2048$、$N=64$、bf16、32 层：SSM 的状态缓存是 $32\times 2048\times 64\times 2 = 8$ MB，**与序列长度无关**。同样规模的 Transformer（32 层、32 头、每头 128 维）：每个 token 的 KV cache 是 $32\times 2\times 32\times 128\times 2 = 512$ KB，100 万 token 就是 512 GB。差了四个数量级。

这就是第 28 章说的"SSM 的推理优势"。它也解释了 Mamba-3 为什么要做 MIMO：状态缓存小意味着每步的计算量也小，小到 GPU 的算力根本用不上，瓶颈全在"把状态从显存读进来再写回去"的带宽上。第 34 章会展开算这笔账。

## 33.4 SSD：把 SSM 写成四次矩阵乘

### 33.4.1 Listing 1 逐行讲解

Mamba-2 论文的 Listing 1 只有 40 行，却是整篇论文的算法核心。我们完整抄录（这是论文原文，未做改动）：

```python
def segsum(x):
    """Naive segment sum calculation. exp(segsum(A)) produces a 1-SS matrix,
    which is equivalent to a scalar SSM."""
    T = x.size(-1)
    x_cumsum = torch.cumsum(x, dim=-1)
    x_segsum = x_cumsum[..., :, None] - x_cumsum[..., None, :]
    mask = torch.tril(torch.ones(T, T, device=x.device, dtype=bool), diagonal=0)
    x_segsum = x_segsum.masked_fill(~mask, -torch.inf)
    return x_segsum


def ssd(X, A, B, C, block_len=64, initial_states=None):
    """
    Arguments:
        X: (batch, length, n_heads, d_head)
        A: (batch, length, n_heads)
        B: (batch, length, n_heads, d_state)
        C: (batch, length, n_heads, d_state)
    Return:
        Y: (batch, length, n_heads, d_head)
    """
    assert X.dtype == A.dtype == B.dtype == C.dtype
    assert X.shape[1] % block_len == 0

    # Rearrange into blocks/chunks
    X, A, B, C = [rearrange(x, "b (c l) ... -> b c l ...", l=block_len) for x in (X, A, B, C)]

    A = rearrange(A, "b c l h -> b h c l")
    A_cumsum = torch.cumsum(A, dim=-1)

    # 1. Compute the output for each intra-chunk (diagonal blocks)
    L = torch.exp(segsum(A))
    Y_diag = torch.einsum("bclhn,bcshn,bhcls,bcshp->bclhp", C, B, L, X)

    # 2. Compute the state for each intra-chunk
    # (right term of low-rank factorization of off-diagonal blocks; B terms)
    decay_states = torch.exp((A_cumsum[:, :, :, -1:] - A_cumsum))
    states = torch.einsum("bclhn,bhcl,bclhp->bchpn", B, decay_states, X)

    # 3. Compute the inter-chunk SSM recurrence; produces correct SSM states at chunk boundaries
    # (middle term of factorization of off-diag blocks; A terms)
    if initial_states is None:
        initial_states = torch.zeros_like(states[:, :1])
    states = torch.cat([initial_states, states], dim=1)
    decay_chunk = torch.exp(segsum(F.pad(A_cumsum[:, :, :, -1], (1, 0))))
    new_states = torch.einsum("bhzc,bchpn->bzhpn", decay_chunk, states)
    states, final_state = new_states[:, :-1], new_states[:, -1]

    # 4. Compute state -> output conversion per chunk
    # (left term of low-rank factorization of off-diagonal blocks; C terms)
    state_decay_out = torch.exp(A_cumsum)
    Y_off = torch.einsum('bclhn,bchpn,bhcl->bclhp', C, states, state_decay_out)

    # Add output of intra-chunk and inter-chunk terms (diagonal and off-diagonal blocks)
    Y = rearrange(Y_diag + Y_off, "b c l h p -> b (c l) h p")
    return Y, final_state
```

先看形状约定。这里的 $A$ 是 `(batch, length, n_heads)`，也就是标量，不是对角矩阵。这正是 Mamba-2 相对 Mamba-1 的简化：$A_t$ 从"$N$ 个对角元"退化成"一个标量"。Mamba-2 论文 §2.4 说这个改动"略微降低表达力，换来巨大的训练效率提升"。代价是 Mamba-2 的 $A$ 无法表达不同状态维度的不同衰减率，只能整体缩放。Mamba-3 把它部分补回来了（复值 $A+i\Theta$，第 30 章）。

`X` 是 `(b, l, h, p)`，其中 `p` 是 head dimension $P$，`h` 是 head 数，`n` 是 state dimension $N$。$P$ 和 $N$ 是两个独立的轴，这是 Mamba-2 与 Mamba-1 的另一个关键差别（Mamba-1 的 $P=1$）。

### 33.4.2 第一步：对角块（块内注意力）

```python
    L = torch.exp(segsum(A))
    Y_diag = torch.einsum("bclhn,bcshn,bhcls,bcshp->bclhp", C, B, L, X)
```

`A` 已经被 rearrange 成 `(b, h, c, l)`，所以 `segsum(A)` 给出 `(b,h,c,l,l)`，`[t,s]` 项是 $\sum_{s<i\le t}A_i$，`exp` 之后是 $\prod_{s<i\le t}a_i$，其中 $a_i = e^{A_i}$。这就是 1-SS 矩阵（下三角、对角为 1）。

四个下标分别读：`b`=batch、`c`=chunk、`l`/`s`=块内时间、`h`=head、`n`=state、`p`=head dim。所以这个 einsum 计算的是

$$Y^{\text{diag}}_{c,t,p} = \sum_{n}\sum_{s\le t} C_{c,t,n}\,B_{c,s,n}\,L_{c,t,s}\,X_{c,s,p}$$

对应论文式 (16) 的第一项 $((L\circ C B^\top)X)_{jj}$。它的结构和注意力一模一样：$C$ 扮演 $Q$、$B$ 扮演 $K$、$X$ 扮演 $V$、$L$ 扮演因果掩码（只不过不是 0/1 而是衰减）。所以这一步可以直接调用 FlashAttention 式的 kernel。

### 33.4.3 第二步：块内状态（右因子）

```python
    decay_states = torch.exp((A_cumsum[:, :, :, -1:] - A_cumsum))
    states = torch.einsum("bclhn,bhcl,bclhp->bchpn", B, decay_states, X)
```

`A_cumsum[..., -1:] - A_cumsum` 是"从当前步到块末的累积衰减"，即 $\prod_{i=t+1}^{C-1}a_i$。所以

$$h^{\text{chunk}}_{c,n,p} = \sum_{t} B_{c,t,n}\left(\prod_{i>t}a_i\right)X_{c,t,p}$$

这是"假设块初状态为 0，块末的状态是多少"。论文 §6.2 把它叫"right factor"或"$B$-block-factor"，对应半可分矩阵低秩分解的 $B$ 部分。

为什么需要这个？因为块与块之间的信息只能通过状态传递。第 $c$ 块的输出要受第 $0..c-1$ 块影响，而那些块的影响全部浓缩在"第 $c$ 块开始时"的状态里。因此必须能算出每个块对状态的贡献。

### 33.4.4 第三步：块间递推（中因子）

```python
    if initial_states is None:
        initial_states = torch.zeros_like(states[:, :1])
    states = torch.cat([initial_states, states], dim=1)
    decay_chunk = torch.exp(segsum(F.pad(A_cumsum[:, :, :, -1], (1, 0))))
    new_states = torch.einsum("bhzc,bchpn->bzhpn", decay_chunk, states)
    states, final_state = new_states[:, :-1], new_states[:, -1]
```

这是全篇最巧妙的一段。`states` 原本有 $L/C$ 个块，每个块的贡献是 $h^{\text{chunk}}_c$。要把它变成"每个块开始时"的真实状态 $h_c$，满足

$$h_c = a_{c-1}h_{c-1} + h^{\text{chunk}}_{c-1}$$

这是一个长度只有 $L/C$ 的标量 SSM 递推。作者的处理方式是：在 `states` 前面拼一个 `initial_states`（形状 `(b,1,h,p,n)`），于是下标变成 $0..L/C$，`states[z]` 表示"第 $z-1$ 块的贡献"。

`F.pad(A_cumsum[..., -1], (1,0))` 在**块级**累积衰减前面补一个 0，得到 `(b,h,L/C+1)`。`segsum` 之后得到 `(b,h,L/C+1,L/C+1)`，`[z,c]` 项是 $\prod_{c<i\le z}a^{\text{chunk}}_i$（$a^{\text{chunk}}_i$ 是第 $i$ 块的总衰减）。于是

$$h_z = \sum_{c\le z}\left(\prod_{c<i\le z}a^{\text{chunk}}_i\right)h^{\text{chunk}}_{c-1}$$

这正是递推的展开式。整个块间递推被写成了一次 $(L/C)\times(L/C)$ 的矩阵乘，而不是一个循环。论文 §6.3 说这一步的成本是 $\text{BMM}(1, T/Q, NP, T/Q)$，因为 $L/C$ 通常只有几十，成本可以忽略。

论文还提到一个工程选择："a naive implementation of this via 1-SS matrix multiplication has cost BMM(1,T/Q,NP,T/Q), which is much easier to implement and can be more efficient than a naive recurrence/scan implementation." 这句话解释了为什么 Listing 1 用矩阵乘而不是 `for` 循环：在小规模上矩阵乘比循环快，即使它渐近更差。

### 33.4.5 第四步：状态到输出（左因子）

```python
    state_decay_out = torch.exp(A_cumsum)
    Y_off = torch.einsum('bclhn,bchpn,bhcl->bclhp', C, states, state_decay_out)
```

`A_cumsum` 是块内从块首到当前步的累积衰减。所以

$$Y^{\text{off}}_{c,t,p} = \sum_n C_{c,t,n}\left(\prod_{i\le t}a_i\right)h_{c,n,p}$$

物理意义：块初状态 $h_c$ 经过 $t+1$ 步衰减后，被 $C_t$ 读出来。这就是"块之前的所有输入"对当前输出的贡献。论文叫它"left factor"或"$C$-block-factor"。

最后 `Y_diag + Y_off` 相加，再 rearrange 回 `(b, (c l), h, p)`。这个加法就是半可分矩阵分块分解的"对角块 + 下三角低秩块"：$Y^{\text{diag}}$ 来自对角块，$Y^{\text{off}}$ 来自所有下三角块的低秩分解。

我们验证过这段代码（$b=2, L=16, h=2, P=3, N=4$，`block_len=4`，`torch.manual_seed(0)`）与逐点递推的等价性：输出最大误差 $1.2\times 10^{-6}$，末状态误差 $2.4\times 10^{-7}$。还验证了 `initial_states` 参数（用于跨序列传递状态）也正确。

### 33.4.6 为什么这样就能用上 Tensor Core

答案很简单：四个步骤全是 `einsum`，而 `einsum` 在 GPU 上会被编译成矩阵乘。

具体看每一步的矩阵乘形状（论文 §6.3 的 BMM 记号）：

| 步骤 | 矩阵乘 | 形状 |
|---|---|---|
| 1. 块内输出 | $C^\top B$ 再乘 $L$ 再乘 $X$ | $\text{BMM}(T/C, C, C, N)$ + $\text{BMM}(T/C, C, P, N)$ |
| 2. 块内状态 | $B^\top(\text{diag}\cdot X)$ | $\text{BMM}(T/C, N, P, C)$ |
| 3. 块间递推 | $L_{\text{chunk}}\cdot H$ | $\text{BMM}(1, T/C, NP, T/C)$ |
| 4. 状态到输出 | $C^\top(\text{diag}\cdot H)$ | $\text{BMM}(T/C, C, P, N)$ |

当 $N = P = C$ 时，所有项都变成 $\text{BMM}(T/N, N, N, N)$：总 FLOPs $O(TN^2)$，总显存 $O(TN)$，**全部是 $N\times N$ 的方阵乘**。论文 §6.3 说 "the memory consumption is tight; the inputs and outputs $x,y$ have shape $(T,P)=(T,N)$"，意思是显存已经达到下界，没有任何浪费。

对比 Mamba-1：它的扫描是逐元素的（每个 $(d,n)$ 独立做标量递推），根本没有矩阵乘，Tensor Core 完全用不上。这就是 2–8 倍差距的来源（Mamba-2 论文 §9.3）。

## 33.5 三种实现的显存与时间直觉

回到开头那个问题：为什么 Mamba-1 非得写 CUDA kernel，而 SSD 用纯 PyTorch 就能跑得不错。

### 33.5.1 Mamba-1 的困境：算术强度太低

Mamba 的扫描每处理一个 token、一个通道、一个状态，做的是

$$h \leftarrow \bar a\cdot h + \bar b\cdot x,\qquad y \mathrel{+}= c\cdot h$$

也就是 3 次乘加，读写 2 个数（$h$ 读一次写一次）。只看这一步，算术强度大约是 $3\text{ FLOPs} / (4\text{ bytes}) \approx 0.75$ ops/byte。把整个 block 的投影都算进去，Mamba-3 论文 Table 2a 给出的数字是约 2.5 ops/byte；而 H100 的 bf16 矩阵乘是 295 ops/byte（Mamba-3 论文 §3.3 引用的数字）。差了两个数量级，扫描因此成为彻底的访存瓶颈，GPU 的算力单元绝大部分时间在空转。

如果按教科书方式实现：

1. 算 $\bar A, \bar B$，写到 HBM，形状 $(B,L,D,N)$；
2. 调并行扫描，读 $(B,L,D,N)$，写 $(B,L,D,N)$；
3. 读回来，乘 $C$，写 $(B,L,D)$。

光是第 1、2 步之间的搬运就是 $2\times BLDN$ 个元素（写一遍、读一遍）。$B=8,L=2048,D=2048,N=16$ 时 $BLDN = 5.4\times 10^{8}$，bf16 下来回就是 2 GB 的流量。而真正有用的输出只有 $BLD = 3.4\times 10^7$ 个元素，多搬了 $2N = 32$ 倍。

Mamba 论文 Appendix D 的解法是核融合（kernel fusion）：

> "We read in $O(BLD+DN)$ bytes of memory $(\Delta, A, B, C)$ from slow HBM to fast SRAM. We discretize to produce $\bar A,\bar B$ of size $(B,L,D,N)$ in SRAM. We perform a parallel associative scan, yielding intermediate states of size $(B,L,D,N)$ in SRAM. We multiply and sum with $C$, producing outputs of size $(B,L,D)$ and write it to HBM."

那句 "in SRAM" 是重点：中间那三个 $(B,L,D,N)$ 的张量从来没进过 HBM。HBM 只负责搬运输入参数和最终输出，IO 量从 $O(BLDN)$ 降到 $O(BLD+DN)$，减少了 $N$ 倍。论文说这在实践中带来 20–40 倍加速（Appendix D，引用 §4.5 的测量）。

但 SRAM 很小（H100 每 SM 228 KB），装不下整段序列。所以还得**分块**：把序列切成能塞进 SRAM 的块，逐块融合扫描，块间传递状态。这就是 "chunked scan"。

### 33.5.2 反向传播：重计算

前向不存中间状态，反传就没有 $h_t$ 可用。Mamba 的选择是重计算（recomputation）：反传时把输入重新从 HBM 读进 SRAM，重新跑一遍前向，边跑边算梯度。

这笔账是划算的，因为：

- 存下来要写 $O(BLDN)$ 到 HBM，反传再读 $O(BLDN)$，共 $2BLDN$；
- 重计算只要读 $O(BLN+DN)$ 的输入，算力开销是重跑一次前向。

在访存瓶颈的场景下，用算力换算力总是赚的。论文 Appendix D 说："since the inputs $\Delta, A, B, C$ and output gradient read from HBM to SRAM are of size $O(BLN+DN)$, and the input gradients are also of size $O(BLN+DN)$, recomputation avoids the cost of reading $O(BLND)$ elements from HBM."

论文还给了一个显存账本，数字值得记住：混合精度（FP16/BF16）下，每个 attention 层每 token 存约 12 字节激活，每个 MLP 层约 20 字节，每个 selective SSM 层约 16 字节。所以"两个 SSM 层的激活显存 ≈ 一个 attention 层 + 一个 MLP 层"。这解释了为什么 Mamba 的显存曲线和同参数量的 Transformer 差不多：它用两个 SSM 层换掉了 attention+MLP。

### 33.5.3 SSD 的幸运：它本来就是矩阵乘

SSD 没有这个问题，因为它的四个步骤都是矩阵乘。矩阵乘的算术强度高（$O(N)$ 而非 $O(1)$），Tensor Core 能吃满，HBM 带宽不再是瓶颈。

更妙的是，分块本身就是算法的一部分，不是为了适配硬件硬加的。所以：

- 不需要自定义 CUDA kernel，用 `einsum` 就行（Listing 1 就是纯 PyTorch）；
- 不需要重计算，因为中间量（$C\times C$ 的 mask、$N\times P$ 的 states）本来就小；
- 显存是 $O(TN)$，已经达到理论下界。

这就是 Mamba-2 论文摘要里 "2-8× faster" 的实质：算法形状终于和硬件形状对上了，而不只是算法更聪明。

### 33.5.4 一张对照表

| | S4D | Mamba-1（S6） | Mamba-2（SSD） |
|---|---|---|---|
| 时间维并行方式 | FFT 卷积 | 并行扫描 | 分块矩阵乘 |
| 训练 FLOPs | $O(BLD\log L)$ | $O(BLDN)$ | $O(BLN^2)$ |
| 训练显存 | $O(BLD)$ | $O(BLD)$（融合后） | $O(BLN)$ |
| 能否用 Tensor Core | 部分（FFT 有专用单元） | **不能** | **能** |
| 需要自定义 kernel | 否（但要避免 $O(NL)$ 显存） | **是** | 否 |
| 推理形式 | 递推 | 递推 | 递推 |
| 推理缓存 | $O(DN)$ | $O(DN)$ | $O(HNP)$ |
| 时变参数 | 不支持 | 支持 | 支持 |

最后一行是分水岭：S4D 是 LTI 的，所以能用卷积；一旦要选择性，就必须放弃卷积，走上"扫描或分块"的路。Mamba-1 选了扫描（省 FLOPs 但吃不满硬件），Mamba-2 选了分块（多花 FLOPs 但吃满硬件），本质上都是用算力换带宽。

## 33.6 本章小结

- S4D 的全部内容就是四行：参数化（`A = -exp(log_A_real) + i*A_imag`）、双线性离散化（`(1+dtA/2)/(1-dtA/2)`）、Vandermonde 核（`sum_n C_n B_n A_n^l`）、FFT 因果卷积（补零到 $2L$ 取前 $L$）。它的简洁性来自"$A$ 是对角矩阵"这个假设。
- 共轭对称是免费的午餐：只存 $N/2$ 个复数，最后取 `2*Re(.)`，参数量与 $N$ 个实数相同，输出自动为实数。忘了这一步，你会得到一个复数输出，然后在 `F.cross_entropy` 那里报一个莫名其妙的 dtype 错误。
- Vandermonde 核有三种写法：朴素（$O(HNL)$ 显存）、按状态循环（$O(HL)$ 显存）、并行扫描（$O(\log L)$ 深度）。选哪种取决于 $N$ 和显存预算。S4D 论文明确指出理论上可以做到 $O(N+L)$，但那需要自定义 kernel。
- S6 与 S4 的差别只有四行（$B,C,\Delta$ 变成 $x$ 的函数），但这四行让卷积失效，只能用扫描。这是数学上的必然，不是实现细节：时变系统的核不是 Toeplitz 的。
- Mamba-1 的实现用的是指数-欧拉离散化（$\bar B = \Delta B$），不是论文正文写的 ZOH。Mamba-3 论文 §3.1 正式证明了这一点并给了它名字。两者在 $\Delta A$ 小时几乎相同，但指数-欧拉永远不会有 $A^{-1}$ 的奇点。
- `cumsum` 除法技巧会数值崩溃：$\prod \bar A_i$ 在 $L=600$ 时就下溢到 0。这也是 SSD 必须分块的原因之一，分块把累积长度限制在 $C$ 以内。
- SSD 的四个步骤对应半可分矩阵的四个块：对角块（块内注意力）、右因子（块内状态）、中因子（块间递推）、左因子（状态到输出）。四步全是 `einsum`，所以能用 Tensor Core。
- 训练用并行、推理用递推，这是约束而非偏好：训练要反传所以需要整段并行；推理每次一个 token 所以只能用递推。SSM 的推理缓存是常数大小，这是它与 KV cache 最本质的差别。
- Mamba-1 需要自定义 kernel，因为算术强度只有约 2.5 ops/byte（Mamba-3 Table 2a），比 H100 的矩阵乘峰值（约 295 ops/byte）低两个数量级，瓶颈全在 HBM 带宽。核融合把中间状态关在 SRAM 里，重计算把反向的存储换成算力，两者合起来是 20–40 倍加速。
